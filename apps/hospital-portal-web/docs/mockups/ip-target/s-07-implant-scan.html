All outcomes of a scan

One barcode can end in six different places. Only the first charges the patient; the panel makes the destination explicit every time, because the difference between a charge, a write-off and a return is the difference between revenue leakage and an accurate margin.

The charged column is a read from Auth, refreshed as the outbox drains. It shows “Posting…” briefly and then the amount. If it stays unposted the item appears in S-15 as implanted-not-charged — the theatre never has to chase it, and it is never silently dropped either.
Today this list cannot be built. There is no implant usage table and no GET /journeys/{id}/implants. The only existing write is POST /api/ip-management/journeys/{id}/verify-iol-barcode, which validates a barcode against iol_catalog_master and stamps IOL fields on patient_journey — one lens per journey, no returns, no consumables, no history. That single-value limitation is the whole reason for gap 5.
