The ledger, and what each action appends to it

Every mutation on this screen appends a line. Nothing is edited and nothing is deleted, which is what makes the bill reconstructable from its own history. The header figures are recomputed from the ledger by OpdBillLedgerCalculator after every change rather than being incremented in place.

Concurrency

Optimistic locking to build

The design needs mutations to carry a version so a stale write is rejected and the UI refreshes rather than overwriting another cashier’s work. No such token exists on any billing entity today, so the last write currently wins silently. Gap 6.

Idempotency exists

Payments carry a client key, unique per (tenant_id, idempotency_key). A replay returns the original bill rather than a duplicate line or a second receipt. Refund payouts reuse refund:{refundId} for the same reason.

Async charges

Charges arrive from theatre while the bill is open. The UI listens on NotificationHub for PaymentReceived and PatientObligationChanged and shows “new charges added” rather than silently changing the total under the user.
