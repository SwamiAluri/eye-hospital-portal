Nothing on this step is editable from the pre-op workspace. A ward nurse can see the financial position because it affects the conversation with the patient, but coverage is written by CCMS and money is written by Billing. This step displays; it never mutates.
Patient due ₹90,000 does not block Mark Ready. It blocks OT acceptance for payers that require pre-authorisation, and it blocks discharge. Stating which gate each amount affects prevents the ward from holding a patient unnecessarily.

Read through GET /api/ip-management/journeys/{id}/billing, which proxies Auth. There is deliberately no Add control on this step — the ward can see the money but cannot move it. Collection happens at the cashier through S-03, which writes the opd_bill_payments ledger and issues a numbered receipt.

This is the one step in the workspace with no Add action, and that is deliberate. Every other step gains one; here the absence is the design. A ward-side money entry form is exactly the dual write path being removed from S-10.
